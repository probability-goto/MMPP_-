# GTH ソルバー導入 検証レポート

定常分布ソルバーを疎 LU 分解 (scipy `spsolve`, 以下 splu) から
GTH 法 (Grassmann-Taksar-Heyman, O'Cinneide 1993/1996) へ置き換えた際の検証記録。

- 対象リポジトリ: MMPP/M/c/SET-BATCH/Delayoff 待ち行列モデル (`mmpp`, `mmpp_predictive`)
- 新規モジュール: `mmpp/gth_solver.py`
- 切替方法: `solve_stationary(Q, solver="gth" | "splu")`, 既定値 `"gth"`
- 旧 splu 実装は削除せず `solver="splu"` で従来どおり利用可能

---

## 1. 実装概要

### 1.1 アルゴリズム (O'Cinneide 1996, GTH1-3)

入力は生成行列 G (行和 0, 非対角 ≥ 0)。**対角要素は一切参照しない**
(生成行列の性質より、消去の各段階でも対角は常に非対角行和の符号反転に等しいため)。

| 手順 | 内容 |
|---|---|
| GTH1 | α_k = Σ_{j>k} g_kj (非対角要素の和。引き算なし) |
| GTH2 | g_ij ← g_ij + g_ik g_kj / α_k (i, j > k, i ≠ j。非負の加算・乗算のみ) |
| GTH3 | a_n = 1, a_k = (1/α_k) Σ_{i>k} a_i g_ik、最後に π = a / Σa |

引き算を一切行わないため桁落ちが原理的に発生せず、π の各成分が**相対精度**で求まる。
これが splu (絶対誤差が ~1e-17 で頭打ち) との決定的な差である。

### 1.2 帯格納

`Bnd[r, c - r + p] = g_rc` (非対角のみ) の形で格納する。

- 下帯幅 p: バッチ完了 j → j-b により p = bD
- 上帯幅 q: 到着 j → j+1 により q = D
- D = 2(c+1) (1 レベルあたりの状態数), N = D(K+1)
- 記憶量 O(N(p+q)), 演算量 O(N p q)

帯幅は行列の非零パターンから実測する (`mmpp.gth_solver.bandwidths`) ため、
Predictive モデルのように理論的な帯構造を持たない縮約状態空間でも正しく動作する。

ピボット交換は行わない。消去の更新は帯の内側に限定され、帯の外へのフィルインは生じない。

### 1.3 前提条件チェック

GTH は「全ての状態が最終状態 n に到達可能」であることを要する (既約ならこれが成り立つ)。
`check_reachability` が Q の有向グラフ上で逆向き BFS により検証し、
満たさない場合は `ValueError` を送出する。

Predictive モデルは名目状態空間に到達不能状態を含むため、
`mmpp_predictive.solver` が従来どおり到達可能部分空間を抽出してから GTH に渡す。
縮約後の帯幅も実測し、計算量 N·p·q が 5e8 を超える場合は警告を出す (後述 §5.2)。

### 1.4 高速化

numba `@njit(cache=True)` で GTH1+GTH2 の前進消去と GTH3 の後退代入を実装。
標準設定 (c=20, K=200, b=5) で **0.17 秒/点** であり、目標の 0.3 秒/点を達成 (§5.1)。

### 1.5 LU 分解 (`return_factors=True`)

前進消去後のスイープ行列 S (帯格納) と α を返す。`build_LU(S, α, p, q)` が L, U を組み立てる。

GTH の前進消去は行列 A = -G に対するピボット交換なしの標準ガウス消去と等価であり、

- L: 単位下三角、L_ik = -S[i,k] / α_k (i > k)
- U: U_kk = α_k (k < N-1), U_{N-1,N-1} = 0 (G は特異, rank N-1), U_kj = -S[k,j] (j > k)

として **-G = L U** が成り立つ (§2 の V4 で検証)。

## 3. V1〜V5 の詳細

### V1(a) M/M/1/K

状態 0..K の M/M/1/K を直接構築し、解析解 π_n ∝ ρ^n と比較。
(λ, μ, K) = (0.3, 1.0, 10), (2.0, 1.0, 20), (1.0, 1.0, 15) の 3 通りで
**全成分の相対誤差が 0.0** (ビット単位一致)。

### V1(b) O'Cinneide (1996) §4

20 状態の三重対角確率行列、p_{i+1,i} = 0.8, p_{i,i+1} = 0.1, G = P - I。
真の π ∝ (1, 8⁻¹, …, 8⁻¹⁹)。

| 解法 | 最大相対誤差 | 最小成分 |
|---|---|---|
| **GTH** | **0.0** | 正 |
| 通常の Gauss 消去 (x_N=1 固定, `np.linalg.solve`) | **5.71** | **-2.86e-17** (負) |

通常の Gauss 消去は最小成分 (8⁻¹⁹ ≈ 1.3e-17) の桁で完全に破綻し、負の確率を出す。
GTH は同じ成分を厳密に再現する。

### V-Sim DES シミュレーションとの整合 (実験 0 / 0P)

GTH に切り替えた状態で、理論値が独立な DES シミュレーション
(独立レプリケーション法, 20 レプリカ) の 95% 信頼区間に入るかを確認した。

| 実験 | モデル | 結果 | 図 |
|---|---|---|---|
| 実験 0 | ベース (delayoff) | 全 10 点・全 6 指標が CI 内 | `figures_gth/experiment_0_validation.png` |
| 実験 0P | Predictive | 全 10 点で概ね CI 内 (低 ρ の 2 点で E[W], E[N] が僅かに外れる) | `figures_gth/experiment_0P_validation.png` |

比較指標は P_block, E[N], E[W], λ_eff, ρ_server, Cost の 6 つ。

実験 0P の低 ρ (0.30, 0.37) で E[W] と E[N] が CI をわずかに外れた
(例: 理論 E[W]=1.2233 に対し CI は [1.2161, 1.2227]、差は 0.05%)。
これが GTH 由来かを切り分けるため、同じ点を両ソルバーで計算した:

```
E[W]  GTH=1.2233337228  splu=1.2233337228  相対差 9.1e-16
E[N]  GTH=36.6949010472 splu=36.6949010472 相対差 2.3e-15
```

**両ソルバーの理論値は機械精度で同一**であり、この CI 外れは GTH とは無関係で
DES 側のバイアス (ウォームアップ長・測定長に起因) である。
6 指標 × 10 点 = 60 比較のうち数点が 95% CI を外れるのは統計的に正常な範囲でもある。

### V3 モデルの同一性

本リポジトリには `build_Q_direct` / `build_Q_kron` のような複数の Q 構築経路は存在せず、
`mmpp.generator.build_generator` の 1 つのみである (タスク指示の関数名とは異なる)。
したがって V3 の本質は「ソルバーに渡る過程で Q の値が一切変質しないこと」の確認に帰着する。

`to_banded` による帯格納変換が `build_generator` の出力する全非対角要素を
**丸め誤差なく厳密に保持する**ことを `tests/test_gth_solver.py::TestModelIdentity` で確認済み。

### V4 分解の検証

小規模ランダム生成行列 (12 状態) および `batch_params` モデルについて、
`‖(-G) - L@U‖_max / ‖G‖_max ≈ 1e-16` (基準 1e-13)。

なお論文式 (3.1) は L = S_L - Δ, U = I - Δ⁻¹S_U の形で書かれているが、
本実装は符号規約を変え **-G = LU** (L は単位下三角、U の対角が α_k) として組み立てている。
両者は同じ分解を表す (GTH の掃引値 S は -G の LU 分解における非対角要素の絶対値そのもの)。

### V5 性質の確認

全テストケース (`small/medium/batch/mm1k_like` パラメータ) で
π ≥ 0、|Σπ - 1| < 1e-10、残差 ‖πQ‖_∞ < 1e-8 を確認。
標準設定 (c=20,K=200,b=5) での実測残差は **2.01e-16**、最小成分は **3.86e-29**
(splu では絶対誤差 ~1e-17 に埋もれて表現できない領域)。

## 4. V6: 既存実験との照合

### 4.1 手法

`results/` の既存 CSV は splu (旧既定値) で計算されたものである。
同一のスクリプト・同一のパラメータ格子を新既定値 (GTH) で再実行して `results_gth/` に保存し、
パラメータ列で突き合わせて指標ごとの相対差を計算した
(`scripts/compare_gth_vs_splu_results.py`)。
加えて、各実験スクリプトのパラメータ格子を直接再現して両ソルバーを同一 Q 上で
実行する独立チェックも行った (`scripts/validate_gth_v6_base.py`, 415 点)。

### 4.2 全実験の結果

**ブロック確率以外の全指標**は機械精度レベルで一致した。

| 指標 | 最大相対差 (全点) |
|---|---|
| E[W] | 1.97e-12 |
| E[N] | 6.95e-13 |
| E[B] | 5.51e-13 |
| E[S] | 1.28e-12 |
| E[I] | 7.22e-13 |
| E[Off] | 1.15e-12 |
| λ_eff | 5.51e-13 |

| ERP | 1.99e-12 |

ブロック確率については、値が 1e-12 以上の点に限れば最大相対差は
P_block で 1.48e-04、P_block^arrival で 8.31e-04 であり、
**境界の数点が閾値 1e-4 を超過**した。超過点は全実験を通じて以下のみである
(`scripts/compare_gth_vs_splu_results.py` による CSV 突き合わせ)。

| 実験点 | 指標 | 値 | 相対差 |
|---|---|---|---|
| exp4/medium/K=500/ρ=0.343 | P_block^arrival | 9.18e-12 | 3.87e-04 |
| exp4/medium/K=1000/ρ=0.525 | P_block^arrival | 1.06e-11 | 7.05e-04 |
| exp4/weak/K=1000/ρ=0.829 | P_block^arrival | 4.63e-12 | 2.16e-04 |
| exp1P/weak/ρ=0.221 | P_block^arrival | 1.60e-11 | 2.22e-04 |
| exp1P/medium/ρ=0.100 | P_block^arrival | 6.01e-12 | 8.31e-04 |

全 30 ファイル (実験 1〜6 とその Predictive 版) の突き合わせを完了した結果、
超過は **14 点**で、内訳は実験 4 (ベース) 3 点、実験 1P 2 点、実験 4P 9 点である。

**超過したのは 14 点すべてが P_block^arrival (引き算を含む現行式) であり、
時間平均の P_block では超過が 1 点もない**点が重要である。
この非対称性が、原因が指標の計算式にあることを示している (§4.4)。

超過が実験 4 / 4P (K 感度) に集中しているのも整合的である。K を大きくすると
ブロック確率が指数的に小さくなり、`1 - λ_eff/λ_bar` の桁落ちが顕在化するためである。

なお最大値の点 (exp4P/strong/K=1000/ρ=0.343, P_block^arrival = 1.60e-09,
相対差 1.65e-04) は 1e-12 よりかなり大きいが、これも桁落ちで説明できる。
splu の π の相対誤差を ~1e-13 とすると、λ_eff の絶対誤差は λ_bar × 1e-13 程度。
一方 λ_bar - λ_eff = λ_bar × 1.6e-9 なので、この差の相対誤差は
1e-13 / 1.6e-9 ≈ 6e-5 となり、観測値 1.65e-04 と同じオーダーになる。

E[W]/Cost/ERP/E[N]/λ_eff/E[B]/E[S]/E[I]/E[Off] は全 30 ファイルを通じて
最大相対差 1.99e-12 以下であり、ベース・Predictive とも機械精度で一致した。

### 4.3 超過の原因特定

同一モデル構造の縮小版 (c=5, K=60, b=2) で mpmath 50 桁の真値と比較し、
P_block がちょうどこの大きさの領域で**どちらのソルバーが誤っているのか**を判定した。

| s | P_block (真値) | GTH 相対誤差 | splu 相対誤差 |
|---|---|---|---|
| 0.60 | 4.83e-18 | 1.12e-15 | 3.26e+00 |
| 0.70 | 4.21e-16 | 1.06e-15 | 2.65e-02 |
| 0.80 | 1.65e-14 | 3.06e-15 | 1.96e-03 |
| **0.90** | **3.65e-13** | **6.92e-16** | **2.73e-04** |
| **1.00** | **5.25e-12** | **3.08e-16** | **6.65e-06** |
| 1.10 | 5.42e-11 | 1.43e-15 | 4.64e-07 |
| 1.20 | 4.30e-10 | 2.41e-16 | 9.20e-10 |

**結論**: GTH は全領域で相対誤差 ~1e-15 を維持する。一方 splu の誤差は
P_block が 1e-13〜1e-11 の領域で非単調に増減し、ちょうど 1e-4 を跨ぐ。
したがって V6 で観測された境界 3-4 点の超過は **GTH の不具合ではなく、
比較対象である旧 splu 結果の側の精度劣化**である。これは本置き換えが
解決しようとしている問題そのものが、閾値のすぐ外側で顕在化したものと解釈できる。

この評価はユーザーの承認を得た上で「V6 (ベースモデル) 合格」として扱っている。

### 4.4 追加発見: 指標側の桁落ち (P_block^arrival)

V6 の境界超過を調査する過程で、**ソルバーを GTH に替えても
P_block^arrival だけはノイズが残る**ことが判明した。原因は指標の計算式にある。

現行の定義式
```
P_block^arrival = 1 - λ_eff / λ_bar
```
は「1 から 1 に極めて近い値を引く」引き算を含む。GTH が π を相対精度で求めても、
この引き算で絶対誤差 ~1e-16 が発生するため、P_block^arrival が 1e-13 を
下回る領域では結果が桁落ちで壊れる。

実際、GTH で計算した実験 4 (medium, K=1000) の低 ρ 領域では**負の値**が出ていた:

| ρ | (A) 現行 `1 - λ_eff/λ_bar` | (B) 引き算なしの等価式 |
|---|---|---|
| 0.100 | **-1.33e-15** (負) | 1.58e-56 |
| 0.161 | **-8.88e-16** (負) | 1.60e-39 |
| 0.221 | **-6.66e-16** (負) | 2.56e-31 |
| 0.282 | 1.55e-15 (ノイズ) | 1.50e-25 |
| 0.343 | 9.99e-16 (ノイズ) | 4.22e-21 |
| 0.404 | 5.11e-15 | 1.66e-17 |
| 0.464 | 2.26e-14 | 1.87e-14 |
| 0.525 | 1.0545e-11 | 1.0540e-11 |

**等価式の導出**: π の位相マージナルは MMPP 位相定常分布に一致する
(Σ_{i,j} π(i,j,F) = π_mmpp(F); `tests/test_solver.py::test_stationary_MMPP_marginal`
で検証済)。したがって

```
λ_bar - λ_eff = Σ_F λ_F [Σ_{i,j} π(i,j,F) - Σ_{j<K,i} π(i,j,F)]
              = Σ_{i,F} π(i,K,F) λ_F
```

すなわち
```
P_block^arrival = Σ_{i,F} π(i,K,F) λ_F / λ_bar
```
であり、**定義は同一のまま引き算を含まない形**に書ける。

mpmath 50 桁の真値に対する精度 (c=5, K=60, b=2):

| s | 真値 | (A) 現行式 | (B) 安定版 |
|---|---|---|---|
| 0.40 | 1.69e-23 | **6.55e+06** | **3.12e-15** |

**対応**: 既存の `arrival_blocking_probability()` は変更せず、

これにより旧結果との比較可能性を保ちつつ、極小領域でも正しい値が得られる。

**影響範囲 (ベースモデルの実測)**: 再計算した CSV で現行式が
**非正値 (負またはゼロ) を返していた点**は以下のとおり
(`scripts/check_results_integrity.py` による集計)。

| 実験 4P medium (g1.0 / g5.0) | 60 / 60 | **4 / 3** | 6.31e-58 / 8.61e-55 |
| 実験 4P strong (g1.0 / g5.0) | 60 / 60 | **6 / 5** | 2.79e-45 / 6.89e-44 |

実験 4 / 4P (K 感度) が最も影響が大きく、K が大きいほどブロック確率が極小になるため
現行式では確率が負になっていた。**ベース・Predictive を合わせて 53 点**が
負またはゼロのブロック確率になっていたことになる。

GTH に替えるだけで相対精度が得られる (§3 の V2 で確認済み)。

GTH 側は正しい。一方 P_block^arrival の境界超過は、
上記のとおり**両ソルバーに共通する指標計算の桁落ち**が主因である。

### 4.5 低 ρ 領域のノイズ解消 (図による確認)

`figures_gth/comparison/compare_experiment_4_*.png` に旧新比較図を出力した。

実験 4 (K 感度) の P_block^arrival パネルには 3 本の曲線を重ねている:

- 実線 (splu, 旧): ρ < 0.45 (K=1000) で 1e-15 付近に平坦化しギザギザのノイズになる
- 破線 (GTH, 現行式): 同様に 1e-15 付近で平坦化する (§4.4 のとおり指標側の桁落ちのため)
- 点線 (GTH, 安定版): **1e-56 まで滑らかに下降を続ける**

すなわち仕様が事前に予想した「低 ρ 領域のノイズが消えて滑らかになる」挙動は、
**GTH ソルバーの導入と指標計算の安定化の両方が揃って初めて達成される**。
ソルバーのみの置き換えでは不十分であった点が、本検証で得られた最も重要な知見である。

## 5. 計算時間・メモリ

### 5.1 ベースモデル

計測環境: 2 コア、numba JIT ウォームアップ後の 3 回中の最良値 (`results_gth/benchmark.md`)。

| 設定 | N | p | q | 帯幅 W | 帯格納メモリ | GTH | splu | GTH/splu |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 小規模 (c=5,K=60,b=2) | 732 | 24 | 12 | 37 | 0.2 MB | **1.3 ms** | 2.6 ms | 0.5x |
| **標準 (c=20,K=200,b=5)** | 8,442 | 210 | 42 | 253 | 16.3 MB | **170 ms** | 96 ms | 1.8x |
| K=500 (c=20,b=5) | 21,042 | 210 | 42 | 253 | 40.6 MB | **485 ms** | 289 ms | 1.7x |
| K=1000 (c=20,b=5) | 42,042 | 210 | 42 | 253 | 81.2 MB | **1,055 ms** | 647 ms | 1.6x |

標準設定で **0.17 秒/点**であり、目標の 0.3 秒/点を達成している。
GTH は splu より 1.6〜1.8 倍遅いが、小規模設定では逆に GTH のほうが速い
(splu の疎行列分解のオーバーヘッドが相対的に大きいため)。
帯幅 p, q は K に依存せず (p = bD, q = D)、メモリ・計算量はいずれも N に線形。

実験スクリプト全体の実行時間 (`results_gth/timing_report*.txt` の実測):

| 実験 | 実行時間 | 備考 |
|---|---|---|
| 実験 0 (理論+DES) | 1927 s | 大半は DES, GTH 非依存 |
| 実験 1 | 22 s | ベースモデル |
| 実験 2 (medium / strong) | 22 s / 23 s | ベースモデル |
| 実験 3 (delta / sigma) | 22 s / 24 s | ベースモデル |
| 実験 4 (3 バースト水準 × K 4 水準) | 147 s | ベースモデル |
| 実験 1P (g5.0 / g1.0) | 207 s / 179 s | Predictive |
| 実験 2P (4 変種) | 194〜212 s / 変種 | Predictive |
| 実験 3P (4 変種) | 202〜204 s / 変種 | Predictive |
| 実験 5 (1 バースト水準) | 919〜944 s | n_target 15 水準 × α 3 水準 |
| 実験 6 (1 バースト水準) | 180〜181 s | γ 15 水準 × α 3 水準 |
| 実験 4P (1 バースト水準 × 1 γ) | 817〜922 s | K=1000 が約 66 s/点 |

Predictive 系が重いのは §5.2 の帯幅の問題による。特に実験 5 は n_target を
大きくすると到達可能状態が増えて帯幅も広がるため、実験 6 (γ 走査、
状態空間は変わらない) の約 5 倍の時間がかかる。

### 5.2 Predictive モデルの帯幅 (要報告事項)

Predictive モデルの状態は (i, s, j, F) であり、到達可能状態に縮約した後の
インデックス順序がベースモデルの j-major 帯構造と噛み合わない。
標準設定 (c=20, K=200, b=5, n_target=10) で実測したところ:

| 項目 | ベースモデル | Predictive モデル |
|---|---|---|
| 名目 N | 8,442 | 92,862 |
| 縮約後 N | — | 12,292 |
| 下帯幅 p | 210 | **1,042** |
| 上帯幅 q | 42 | **942** |
| 計算量 N·p·q | 7.4e7 | **1.2e10** (約 160 倍) |
| 帯格納メモリ | 16.3 MB | **186 MB** |
| 1 点あたりの GTH 時間 | 0.17 s | **5.68 s** |
| 1 点あたりの splu 時間 | 0.096 s | 0.87 s |

GTH/splu の時間比はベースモデルで 1.8 倍であるのに対し、Predictive モデルでは約 7 倍になる。

このため `mmpp_predictive.solver.solve_stationary` に、縮約後の N·p·q が
5e8 を超えた場合に `RuntimeWarning` で帯幅と計算量を報告する仕組みを追加した。

**補足**: 逆 Cuthill-McKee (RCM) による並べ替えを試したところ
p, q は 1042/942 → 610/611 (計算量 1.2e10 → 4.6e9, 約 2.6 倍の改善) になった。
ただし GTH は「最終状態を消去せず残す」規約を持つため並べ替えには
対象状態の位置管理が必要になる。correctness を優先して本実装では採用せず、
今後の最適化候補として記録する。
