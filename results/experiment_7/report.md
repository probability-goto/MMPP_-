## (1)(2) の判定

以下の数値はすべて上の表 (experiment_7_<条件>.csv と experiment_7_refine_<条件>.csv から計算) による.
Base の β 13 点では格子が粗く, Predictive の系列 (γ や n_target の組み合わせで点が多い) が
有利に見える場合がある (C3 では P1+P2 (protect) が Base のフロンティアの 1/5 点を支配するが,
β を 121 点にした Base に対しては 0/37 点). そこで判定は β を細かくした Base を基準にする.
Predictive の系列は β 13 点のままなので, この基準は Predictive に不利な側に寄っている.

**(1) 位相の情報に, β の調整では得られない価値があるか.**
ある. ただし大きさは小さく, 条件によっては無い.
β を細かくした Base に対する ERP 最小値の相対差は, 位相を使う系列のうち最良のもので
C1 −1.19% (P1+P2 (protect)), C2 −0.32% (P1 only (protect) と P1+P2 (protect)),
C3 −0.28% (P1 only (protect)), C4 −0.23% (P1+P2 (protect)), C5 −0.55% (P1+P2 (protect)) である.
フロンティアでは, P1+P2 (protect) が β を細かくした Base のフロンティアを
C1 で全域 (92/92), C5 で全域 (112/112; 保護なしの P1+P2 も 112/112) 支配し,
C2 で 48/94 点, C4 で 61/89 点を支配する. 同じ E[W] での Cost の削減率の最大値は
C1 +1.47%, C2 +0.41%, C4 +1.49%, C5 +6.32% (E[W] の小さい端) である.
一方, 位相が短い C3 (α/σ=0.1) では, P1+P2 (protect) は 0/37 点しか支配せず,
同じ E[W] での Cost の削減率は 5 水準のどこでも正にならない (最大 −0.05%).
価値の内訳は次のとおりである. 保護なしの P1 only は Base とほぼ同じで
(ERP 最小値の差 −0.14%〜+0.07%), 事前セットアップだけでは効果がない.
P1 に保護を付けると C1 で −1.16% になる (他の条件では −0.05%〜−0.32%).
P2 only (通常位相での Delayoff 加速) はセットアップの速い C5 で −0.53% と効き,
他の条件では −0.11%〜+0.02% である.

**(2) その価値は, 位相を使わずに取り消しを止めるだけ (NoCancel) でも得られるか.**
得られない. NoCancel の ERP 最小値 (β を ERP 最小点の近くで細かくしたもの) は,
β を細かくした Base より 5 条件すべてで大きい
(C1 +0.59%, C2 +2.12%, C3 +8.56%, C4 +0.33%, C5 +0.99%).
NoCancel のフロンティアが β を細かくした Base のフロンティアを支配するのは,
C1 で 13/92 点, C4 で 11/89 点, C5 で 22/112 点だけで, いずれも E[W] が最も小さい端
(C1 で E[W] ≤ 1.065, C4 で ≤ 1.067, C5 で ≤ 1.067; サーバーをほとんど落とさない β の小さい側)
に限られ, ERP 最小点の付近では Base より Cost が高い.
これに対して, 取り消しを止めるのをバースト中かつ i+s ≤ n_target に限った P1 only (protect) は,
5 条件すべてで ERP 最小値が Base より小さい (−1.16%, −0.32%, −0.28%, −0.21%, −0.05%).
したがって, 保護による改善は「取り消しを止めること」そのものではなく,
止める時期を位相の情報で選ぶことによる. 取り消しを位相によらず止めると,
起動中のサーバーが需要の減った後も残り, Cost が上がる (C3 では同じ E[W] で比べた 5 水準のすべてで Cost が 8.85% 以上高い).
