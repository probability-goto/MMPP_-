## パート B: Base の最良の β のまま規則を加える

各マスで Base の ERP 最小点の β* (summary.csv の base_beta) を固定し, 規則を加えた Predictive (保護あり) を同じ β* の Base (= Base の ERP 最小点) と比べる. β は設定ごとに 最適化しない (4 つの設定とも Base の β*). 改善 = ERP が 0.1% 以上下がり, P の比が 1.05 を超えない. 同等 = ERP も P も同等. 棄却のみ改善 = ERP は同等で, P の比が 0.95 未満. 引き換え = 片方が改善し, もう片方が悪化する. 悪化 = どちらかが悪化し, どちらも改善しない.

| 設定 | 規則 | (n_target, γ) | 改善 | 同等 | 棄却のみ改善 | 引き換え | 悪化 |
|---|---|---|---|---|---|---|---|
| presetup nt=10 | 事前セットアップ | (10, 1) | 0 | 15 | 0 | 0 | 0 |
| presetup nt=20 | 事前セットアップ | (20, 1) | 2 | 5 | 0 | 8 | 0 |
| delayoff g=3 | Delayoff の加速 | (0, 3) | 0 | 1 | 0 | 1 | 13 |
| delayoff g=10 | Delayoff の加速 | (0, 10) | 0 | 0 | 0 | 0 | 15 |

注意 (パート A との違い):

- パート B の β は, 4 つの設定とも各マスの Base の ERP 最小点の β* (summary.csv の base_beta) で, 設定ごとに最適化していない. パート A の基準点の β は Predictive の最良点の β* (summary.csv の pred_beta) で, n_target や γ を動かしても β はそのまま. このため (n_target, γ) が同じでも, 2 つのパートの点は β が違えば別の点になる. ERP の相対差と P の比の基準 (Base の ERP 最小値と P_ref) はどちらのパートも同じ.
- n_target = 0 では保護も事前セットアップも働かず (i+s ≤ 0 の状態では Delayoff も取り消しももともと起こらない), 規則は Delayoff の加速だけになる. 切る速さは通常期 γβ, バースト中 β なので, β が違えばどちらの期間の速さも同じ比で変わる.
- ρ_B=0.8, r1=100 (改善率の上位 2, γ* = 3): パート A の n_target=0 の点とパート B の delayoff g=3 は (n_target, γ) が同じだが β が違う. パート A は Predictive の最良点の β* を使う: (β, n_target, γ) = (0.0002812, 0, 3): E[W] = 1.1124, Cost = 4.5175, P = 2.6662e-03, ERP = 5.02515 (相対差 -1.054%, P の比 1.054). パート B は Base の β* を使う: (β, n_target, γ) = (0.000433, 0, 3): E[W] = 1.1292, Cost = 4.4906, P = 2.8742e-03, ERP = 5.07077 (相対差 -0.156%, P の比 1.136). β の比は 1.54.
- どちらのマスでも Base の β* のほうが大きく, パート B の点はどちらの期間も早く台を切る. そのため Cost は下がるが, E[W] と P が上がり, ERP は上がる.
