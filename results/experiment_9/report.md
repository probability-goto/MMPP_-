## パート A: 最良点の周りでの感度

基準点は各マスの (b) の最良点 (P ≤ P_ref の中の ERP 最小点; results/experiment_8/blocking_reassessment.md). ERP の相対差は Base の ERP 最小値に対するもの, P の比は P_ref (Base の ERP 最小点の P) に対するもの. 「Base より悪い」= ERP の相対差 > 0 または P の比 > 1. 各パラメータの範囲は, その格子の上で悪くなる値の区間 (β は基準点の β に対する倍率). 「ERP のみ」は ERP の相対差 > 0 だけで, 「P のみ」は P の比 > 1 だけで判定した範囲で, 両者は重なりうる. 「どちらか」はその和集合. 基準点は P ≤ P_ref の制約の下での最良点なので, P の比は 1 に近いことが多く, β を大きくする (通常期に早く切る) と P が P_ref を超えやすい.

## まとめ

数値はすべて上の表 (experiment_9_{A,B}.csv から計算) による.

**パート A (最良点の周りでの感度).**
- **β**: 基準点の β を 2 倍以上にする (通常期にサーバーを早く切る) と, 12 組のうち 10 組で P が P_ref を超える
  (例外は B_alpha1 r1=3.16 の P1 only (protect) で β×10 でも P_ref 以下, B_alpha10 r1=17.8 の P1+P2 (protect) で
  超えるのは β×10 だけ).
  基準点は P ≤ P_ref の制約の境目近くにある (P の比 0.41〜0.99) ので, β を大きくする側の余裕は小さい.
  β を小さくすると ERP が Base より悪くなり, β×0.1 では 12 組すべてで悪い.
- **n_target**: 改善が大きいマスでは, n_target を基準点より小さくすると悪くなる.
  A_rhoB0.8 r1=17.8 と B_alpha0.005 r1=17.8 の P1 only (protect) (基準点 n_target=20) では, n_target ≤ 16
  (B_alpha0.005 では ≤ 18) で P が P_ref を超え ERP も悪くなる. B_alpha1 r1=3.16 と A_rhoB0.6 r1=3.16 の
  P1 only (protect) (基準点 15) では n_target ≤ 10 と n_target ≥ 16 (A_rhoB0.6) または 20 (B_alpha1) で悪い.
  一方, P1+P2 (protect) は B_alpha0.005 r1=17.8 で n_target をどう変えても悪くならず,
  A_rhoB0.8 r1=17.8 では ERP は悪くならないが n_target ≤ 12 で P が上がる.
- **γ**: P1 only (protect) に γ ≥ 2 を加えると, r1=17.8 の 2 マスと A_rhoB0.6 r1=3.16 で P が上がり悪くなるが,
  B_alpha1 r1=3.16 では γ をどう変えても悪くならない. P1+P2 (protect) は γ を基準点から下げても上げても
  悪くなる範囲がある (例: A_rhoB0.8 r1=17.8 で γ ≤ 30 と γ ≥ 300).
- **対照のマス** (A_rhoB0.8 r1=0.1, B_alpha10 r1=17.8) では, P1 only (protect) の基準点の改善が 0.28% と 0.01% と小さく,
  どのパラメータもほとんどの値で Base より悪くなる (A_rhoB0.8 r1=0.1 の n_target は全域).
  P1+P2 (protect) の基準点は A_rhoB0.8 r1=0.1 (ERP +0.59%) と A_rhoB0.6 r1=3.16 (+0.37%) で Base より悪く,
  A_rhoB0.8 r1=0.1 ではどのパラメータのどの値でも, A_rhoB0.6 r1=3.16 では n_target=14 を除くすべての値で Base より悪い.
  B_alpha10 r1=17.8 の P1+P2 (protect) は基準点で ERP −0.51% で, 悪くなるのは n_target ≥ 12, γ ≤ 2, β×0.1 と β×10.

**パート B (Base の最良の β のまま規則を ON にした場合).**
- **P1 only (protect) n_target=10**: 改善 26 マス, 引き換え 9 マス, 悪化 0 マス. P が上がるマスはない.
  最大の改善は B_alpha1 r1=3.16 の ERP −1.04% (P −17.4%). 引き換えのマス (ERP が 0.00%〜+2.32%, P は下がる) は
  α=10 の全 5 マス, ρ_B=1.12 と α=0.005 の r1 ≤ 0.562.
- **P1 only (protect) n_target=20**: 改善 12 マス, 引き換え 23 マス, 悪化 0 マス. P が上がるマスはない.
  最大の改善は A_rhoB0.8 r1=17.8 の ERP −2.32% (P −29.5%). 引き換えのマスでは ERP が +0.21%〜+53.93% 上がる
  (最大は B_alpha10 r1=0.1 で, P は −47.9%). n_target を大きくしすぎると, P は下がるが ERP が大きく悪化しうる.
- **P2 only γ=3**: 改善 0 マス, 引き換え 10 マス, 悪化 25 マス. 35 マスすべてで P が上がる
  (最大 A_rhoB0.6 r1=0.562 の +1052.8%, ERP +2.71%). 引き換えのマス (r1 ≥ 17.8 と α=10 の r1 ≥ 3.16) でも
  ERP の改善は 0.07%〜0.27%.
- **P2 only γ=10**: 改善 0 マス, 引き換え 3 マス, 悪化 32 マス. P は最大 +12827.5% (A_rhoB0.6 r1=0.562, ERP +17.11%).
- つまり, Base の β* のまま P1 (保護あり) を ON にしても P は上がらず, n_target=10 なら ERP も 26 マスで下がる.
  一方, P2 (通常期の Delayoff 加速) を β* のまま ON にすると, 通常期にサーバーを切りすぎて P がどのマスでも上がり,
  多くのマスで ERP も悪くなる. P2 は β を同時に下げ直さないと Base より悪い.
